# ウズベキスタンNOW ニュース収集ボット

複数のウズベキスタン現地Telegramチャンネルから、**現地で実際に読まれているニュースだけ**を拾い、
日本語のX投稿の下書きを作ります。

```
Telegram 11ch  →  反応で足切り  →  関連度で足切り  →  Claude が選定＋作文  →  下書き / 投稿
   数百件            数十件            十数件              最大3本
```

---

## 「よさそうなニュース」をどう判定しているか

### ① 反応（エンゲージメント）— 最初で最強のフィルタ

Telegramの公開プレビューには**閲覧数**が出ます。これを絶対数ではなく
**「そのチャンネルの直近の中央値に対する比率」**で見ます。

| | 閲覧数 | チャンネル中央値 | 比率 | 判定 |
|---|---|---|---|---|
| Kun.uz の投稿A | 35,000 | 10,000 | **3.5倍** | 通過 |
| Kun.uz の投稿B | 12,000 | 10,000 | 1.2倍 | 落選 |
| 小規模chの投稿C | 9,000 | 2,000 | 4.5倍 | 通過 |

絶対数で切ると大手チャンネルの平凡な投稿ばかり通ります。**比率なら「そのチャンネルにしては
異常に読まれている＝現地の人が本当に反応した」**を、規模に関係なく拾えます。

しきい値は `config.yaml` の `min_view_ratio`（既定 1.5 = 中央値の150%）。
絵文字リアクションも取得を試み、取れた場合は下書きに併記します。

### ② 関連度 — キーワードの重み付け

不動産・都市開発（+3）／経済・投資・日本（+2）／タシケント・インフラ（+1）で加点し、
スポーツ・事件・芸能は除外。合計2点未満は捨てます。

キーワードは**ロシア語・ウズベク語ラテン文字・ウズベク語キリル文字・英語の4系統**を併記しています。
ウズベク語はラテンとキリルの両方が現役で使われているため、片方だけだと取りこぼします
（`Тошкент` と `Toshkent` は同じ語）。またラテン表記の `o'` は `'` `ʻ` `'` などの
表記ゆれがあるので、照合前に正規化しています。

### ③ Claude による選定と作文

ここまでで残った十数件だけをClaudeに渡し、**最大3本**を選ばせて4段構成の投稿文を書かせます。
1日1リクエストなので、API費用は1日あたり数十円程度です。

Claudeには「1本も選ばないことは正しい判断」と明示してあります。**無理に出させません。**

## セットアップ

```bash
cd tools/uz-news-bot
pip install -r requirements.txt
export ANTHROPIC_API_KEY=...
```

## 使い方

```bash
# ① まず無料で挙動を見る（Claudeを呼ばない。絞り込み結果だけ表示）
python -m uznews.cli --dry-run

# ② 下書きを作る（既定モード）。out/YYYY-MM-DD.md に書き出す
python -m uznews.cli

# ③ 確認せずそのまま投稿する（非推奨。理由は下記）
python -m uznews.cli --mode auto --min-confidence 85
```

`--dry-run` でしきい値を調整してから本番に進んでください。
候補が多すぎるなら `min_view_ratio` を 1.8 に、少なすぎるなら 1.3 に下げます。

---

## 完全自動投稿を既定にしていない理由

技術的には `--mode auto` で動きますが、**既定では下書き止まりにしてあります。**

1. **このメディアの差別化は「翻訳の正確さ」そのもの。** Claudeは原文から日本語へ1回で訳しますが、
   それでも数字・単位・固有名詞はずれます。加えて、現地媒体はウズベク語版とロシア語版を
   併売しており、**拾った時点ですでに一度訳されている**記事もあります。
   誤報を1回出した速報メディアは、それだけで信用を失います。
2. **原文にない断定が混じるリスクをゼロにはできません。** 特に規制・制度・価格は危険です。
3. **人の手が入るのは1日3分です。** 下書きは投稿文として完成しているので、
   読んで数字を確認して投稿ボタンを押すだけ。ここを削る価値は小さい。

運用が安定し、生成物の精度に確信が持てたら `--mode auto --min-confidence 90` に上げてください。
その場合も**週に一度は出力を人が読む**ことをおすすめします。

## 自動実行（GitHub Actions）

`.github/workflows/uz-news.yml` が毎朝 8:00 JST に走り、下書きを
`tools/uz-news-bot/out/` にコミットします。リポジトリの Secrets に以下を登録してください。

| Secret | 用途 |
|---|---|
| `ANTHROPIC_API_KEY` | 必須 |
| `X_API_KEY` / `X_API_SECRET` / `X_ACCESS_TOKEN` / `X_ACCESS_TOKEN_SECRET` | `--mode auto` を使う場合のみ |

## 既知の制約

- **Telegram Bot API は使えません。** Bot APIは「自分が管理者のチャンネル」しか読めないため、
  他社のニュースチャンネルは読めません。そこで公開プレビュー `https://t.me/s/<channel>` の
  HTMLを取得しています。**非公開チャンネルは取得できません。**
- **投稿直後のニュースは不利になります。** 閲覧数が伸びきる前だと比率が低く出るためです。
  毎朝1回・前日分を対象にする運用（`lookback_hours: 28`）ならほぼ影響しません。
- **リアクション数は常に取れるとは限りません。** 公開プレビューの描画に依存するため、
  取得できない場合は0として扱い、閲覧数のみで判定します。
- **X API の無料枠には投稿数の上限があります。** `--mode auto` を常用するなら
  有料プランが必要になる可能性があります。下書きモードなら X API は不要です。
- **`config.yaml` に `verified: false` のチャンネルがあります。** ハンドル未確認のため既定では
  対象外です。`t.me/s/<name>` をブラウザで開いて実在を確認してから `true` にしてください。
- **未検証の動作があります。** 開発環境から `t.me` と X API に接続できなかったため、
  HTMLパース・絞り込み・出力は擬似データで検証済みですが、
  **実際のTelegram取得とX投稿は未実行です。** 初回は必ず `--dry-run` から始めてください。

## ファイル構成

| ファイル | 役割 |
|---|---|
| `config.yaml` | チャンネル一覧、しきい値、キーワード |
| `uznews/sources.py` | Telegram公開プレビューの取得とHTMLパース |
| `uznews/filtering.py` | 反応と関連度による絞り込み |
| `uznews/judge.py` | Claudeによる選定と日本語作文 |
| `uznews/publish.py` | 下書きの書き出しとX投稿 |
| `uznews/cli.py` | エントリポイント |
| `state/seen.json` | 既出の記録（同じニュースを二度出さない） |
| `out/YYYY-MM-DD.md` | 日次の下書き |
