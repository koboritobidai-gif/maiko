# Lステップ → KPI表 自動反映

KPI表（`KPI表.xlsx` / シート `（新）20244～`）の週次KPIを、Lステップの標準APIから自動で取得・反映する Google Apps Script です。

## 反映される項目

| KPI表の行 | 項目 | 反映方法 |
|---|---|---|
| 6行目 | **LINE登録人数** | Lステップの友だち登録日時を週次で集計して書き込み |
| 8行目 | **面談予約数** | 友だち情報「面談予約日」を週次で集計して書き込み |
| 9行目 | **面談数** | 友だち情報「面談実施日」を週次で集計して書き込み |
| 7行目 | LINE登録率（2/1） | **シートの既存数式が自動計算**（`=6行/5行`） |
| 10行目 | 面談実行率（5/4） | **シートの既存数式が自動計算**（`=9行/8行`） |
| 11行目 | LINE登録からの面談移行率（5/2） | **シートの既存数式が自動計算**（`=9行/6行`） |

率3種は全週列にすでに数式が入っているため、スクリプトは触りません。
**書き込むのは6・8・9行目の3つだけ**で、率・月計（「計」列）・年間累計は自動更新されます。

シートの列は「1行目の週開始日（月曜）」で特定します。全74週分を検証済みで、
すべて月曜始まり・終了日=開始+6日になっていることを確認しています（`test/run_tests.js`）。

## ⚠️ 着手前に必要な3つの準備

### 1. KPI表を Google スプレッドシート形式に変換する（必須）

現在このファイルは **Excel形式（.xlsx）のまま Drive に置かれています**。
Excel形式のファイルには Apps Script を紐づけられず、`SpreadsheetApp` から開くこともできないため、
**このままでは自動反映は動きません。**

Google スプレッドシートで開き、`ファイル > Google スプレッドシートとして保存` を実行してください。
変換後は新しいファイル（新URL）になるため、以下の点にご注意ください。

- 既存のURL・共有リンクを参照している箇所があれば貼り替えが必要
- ピボットテーブル・一部の書式は変換時に調整が入る場合があるため、変換直後に数式（特に「計」「累計」列）の値が変換前と一致するか確認してください

### 2. LステップのAPI連携オプションを有効にする

API連携は **プロプラン以上のオプション機能**（月額11,000円・税込、Webhook利用中なら+5,500円）です。
管理画面から申し込み後、`API連携 > 認証` でアクセストークンを発行してください。

### 3. 面談予約数・面談数をLステップ側で日付として持たせる

APIから取れる友だち情報には「登録日時」はありますが、**面談の予約・実施は日付として保持していないと週次で数えられません。**
Lステップ側に日付型の友だち情報欄を2つ用意し、自動でセットされるようにしてください。

- 「面談予約日」… 予約完了時のアクションで当日日付をセット
- 「面談実施日」… 面談実施のタグ付け／アクション時に当日日付をセット

この設計にすると「その週に予約が入った件数」「その週に面談を実施した件数」という
**KPI表と同じ“週次イベント数”の定義**で集計できます。
（登録週と面談週がまたがっても正しい週に計上されます。テストで検証済み）

日付欄をすぐ用意できない場合は暫定手段として `CONFIG.MEETING.mode = 'tag'` を使えますが、
この場合は「友だち登録週」に寄せて数えるため実績とずれます。恒久運用には非推奨です。

## セットアップ手順

1. 変換後のスプレッドシートを開き、`拡張機能 > Apps Script`
2. `src/` 配下の5ファイルと `appsscript.json` の内容をコピー
   （`clasp` を使う場合は `clasp create --type sheets` 後に `clasp push`）
3. `プロジェクトの設定 > スクリプト プロパティ` に以下を登録

   | プロパティ名 | 値 |
   |---|---|
   | `LSTEP_ACCESS_TOKEN` | Lステップ管理画面「API連携 > 認証」で発行したトークン |
   | `KPI_SPREADSHEET_ID` | KPI表のスプレッドシートID（バインド型なら不要） |

4. `src/00_Config.gs` の `CONFIG.API` を、Lステップ管理画面の
   **「API連携 > APIリファレンス」の「友だち情報一覧取得」** に合わせて書き換え

   ```js
   API: {
     baseUrl: 'https://…',        // ← リファレンス記載のホスト
     friendsPath: '/…/friends',   // ← 「友だち情報一覧取得」のパス
     method: 'get',               // ← リファレンスのメソッド
     …
   }
   ```

   リファレンス画面の **【cURL実行サンプル】** をコピーすると、URL・メソッド・ヘッダーが確実に分かります。

5. スプレッドシートを開き直す → メニューに **「Lステップ同期」** が追加される
6. **「API接続テスト・項目診断」** を実行
   → 実レスポンスのキー一覧と自動マッピング結果がログに出ます。
   `createdAt` や友だち情報が `null` になっている場合は、ログのキー名を
   `CONFIG.FIELDS` / `CONFIG.MEETING` の候補配列に追記してください。
7. **「書き込まずに確認（直近8週）」** で数字が既存の手入力値と合うか照合
8. 問題なければ **「毎週月曜の自動実行をON」**

## 運用

| メニュー | 動作 |
|---|---|
| 前週分を反映 | 前週（月〜日）の3項目を書き込み。定期実行と同じ処理 |
| 今週分を反映（速報） | 進行中の週の途中集計を書き込み |
| 期間を指定して反映… | `2026-06-01,2026-08-09` のように指定して過去分を一括反映 |
| 書き込まずに確認（直近8週） | シートを変更せず結果だけログ／ダイアログに表示 |
| API接続テスト・項目診断 | 接続確認とレスポンス項目名の確認 |
| 毎週月曜の自動実行をON/OFF | 毎週月曜7時台に前週分を自動反映（既存運用「毎週月曜日に前週の数字を入力」に対応） |

### 手入力との共存

初期設定は `CONFIG.SHEET.overwriteExisting = false` です。
**すでに人が入力しているセルは上書きせず**、Lステップ側の数字と食い違う場合のみ
`Lステップ同期ログ` シートに差分を記録します。

数字を照合して問題なければ `true` に変えると、常にLステップ側の値で更新されます。

### 記録シート

自動で2つのシートが作られます。

- `Lステップ_RAW` … 週次の集計値（監査・突き合わせ用）
- `Lステップ同期ログ` … 実行日時・対象週・書き込み結果・スキップ内容

## 既知の制約・注意点

### LINE登録率は、このスクリプトだけでは出ません

`LINE登録率 = LINE登録人数 ÷ PV数` で、**PV数（5行目）はLステップの管理外データ**です（GA4・広告管理画面などが出所）。
分子（6行目）は自動反映されますが、分母が入らないと率は `-` のままです。

さらに現状、**2026年4月以降（FE列＝4/6週 以降）のPV数セルが壊れた数式になっています。**

```
FE5: =iferror(FE4/FE3,"-")   ← 4行目「1週」÷3行目（空欄）を割っている
```

このため2026年4月以降のLINE登録率はすべて `-` 表示です。
2026年3月（FB列）までは数値が直接入力されていました。
PV数を手入力に戻すか、GA4連携で埋めるかを決めてこの数式を消す必要があります。
（このスクリプトは5行目を触らないため、自動では直りません）

### その他

- 「LINE登録人数」は後からブロックされた友だちも含めて集計します（`CONFIG.COUNT_STATUSES`）。
  “その週に登録した人数”という既存の定義に合わせたものです。除外したい場合は `['normal']` に変更してください。
- `dateField` モードでは、1人が複数回面談した場合、Lステップの日付欄が最新の日付で上書きされるため、
  最後の1件のみ計上されます。再面談を厳密に数える運用なら、Lステップ側で回数用の項目を別途持たせてください。
- 友だち一覧は毎回全件取得しています。友だち数が数万件規模になり実行時間（6分上限）に近づく場合は、
  `CONFIG.API.extraQuery` にLステップ側の絞り込み条件を追加してください。

## テスト

```bash
node test/run_tests.js
```

週境界の計算（月曜始まり／日曜またぎ／年またぎ）、日付パース、週次集計、
および **実際のKPI表から書き出した全74週分の列マップ**との突き合わせを検証します。
