# Lステップ → KPI表 自動反映

KPI表（シート `（新）20244～`）の週次KPIを自動で集計・転記する Google Apps Script です。

## 反映される項目

| KPI表の行 | 項目 | 反映方法 |
|---|---|---|
| 6行目 | **LINE登録人数** | LINE統計API（近似）／ Lステップ API・CSV（実数） |
| 8行目 | **面談予約数** | Googleカレンダーの予約イベント数 |
| 9行目 | **面談数** | カレンダーで「面談済」が付いたイベント数 |
| 10行目 | 面談実行率（5/4） | **シートの既存数式が自動計算**（`=9行/8行`） |
| 11行目 | LINE登録からの面談移行率（5/2） | **シートの既存数式が自動計算**（`=9行/6行`） |
| 7行目 | LINE登録率（2/1） | 分母のPV数（5行目）がLステップ外のデータのため対象外 |

率は全週列にすでに数式が入っているため、スクリプトは触りません。
**書き込むのは6・8・9行目の3つだけ**で、率・月計（「計」列）・年間累計は自動更新されます。

シートの列は「1行目の週開始日（月曜）」で特定します。全74週分が月曜始まり・
終了日=開始+6日であることを検証済みです。

## 取得ルート（推奨順）

### ルート0：Googleカレンダー ＋ LINE統計API 【費用ゼロ・完全自動・推奨】

**面談予約はすでにLステップからGoogleカレンダーへ自動連携されています。**
（イベント本文に `[Lステップから連携]` が入っているものがそれです）
つまり面談まわりの数字は、Lステップにログインしなくてもカレンダーを読むだけで取れます。

実際のカレンダーとKPI表の手入力値を突き合わせた検証結果：

| 週 | 面談数（カレンダー） | 面談数（KPI表の手入力） | |
|---|---|---|---|
| 2026-07-20週 | 7 | 7 | ✅ 一致 |
| 2026-07-27週 | 4 | 4 | ✅ 一致 |
| 2026-07-20週 面談予約数 | 11 | 11 | ✅ 一致 |

LINE登録人数は、LINE公式アカウントの Messaging API 統計エンドポイント
（`GET /v2/bot/insight/followers`、**追加料金なし**）から求めます。
ただしこれは近似値です（後述）。

- **必要なもの**：なし（LINE Developers のチャネルアクセストークンのみ、無料）
- **人の操作**：ゼロ

### ルートA：Lステップ API連携

Lステップの標準APIから直接取得。LINE登録人数も実数で取れます。

- **必要なもの**：プロプラン以上＋API連携オプション（月額11,000円税込）

### ルートB：CSV取り込み

Lステップからエクスポートした友だちCSVをGoogleドライブのフォルダに置くだけ。
置いた後の集計・転記は自動です。

- **必要なもの**：なし（CSVエクスポートは全プラン共通機能）
- **人の操作**：週1回のエクスポート

3つとも集計・書き込み処理を共有しているので、**後から切り替えても結果は変わりません**。

## ⚠️ 着手前に必要な準備

### KPI表を Google スプレッドシート形式に変換する（全ルート共通・必須）

現在このファイルは **Excel形式（.xlsx）のまま Drive にあります**。
Excel形式のファイルには Apps Script を紐づけられないため、**このままではどのルートも動きません。**

Google スプレッドシートで開き、`ファイル > Google スプレッドシートとして保存` を実行してください。
変換後は新しいファイル（新URL）になるので、共有リンクの貼り替えと、
変換直後に「計」「累計」列の数値が変換前と一致するかの確認をおすすめします。

## セットアップ手順（ルート0）

1. 変換後のスプレッドシートを開き、`拡張機能 > Apps Script`
2. `src/` 配下のファイルと `appsscript.json` の内容をコピー
   （`clasp` を使う場合は `clasp create --type sheets` 後に `clasp push`）
3. LINE登録人数を使う場合のみ、`プロジェクトの設定 > スクリプト プロパティ` に登録

   | プロパティ名 | 値 |
   |---|---|
   | `LINE_CHANNEL_ACCESS_TOKEN` | LINE Developers コンソール > 対象チャネル > Messaging API設定 で発行 |

   面談数だけ自動化する場合は不要です（カレンダーのみで動きます）。
4. スプレッドシートを開き直す → メニュー **「Lステップ同期 > カレンダー＋LINE統計（費用ゼロ）」**
5. **「カレンダーの数字を表と照合（書き込みなし）」** を実行し、
   過去数週分が手入力値と合うか確認（例: `2026-06-01,2026-08-09`）
6. ズレがあれば **「拾ったカレンダー予定を一覧表示」** で、
   どのイベントを予約・実施・除外と判定したかを確認し、
   `CONFIG.CALENDAR` のパターンを調整
7. **「LINE統計の数字を表と照合（書き込みなし）」** で近似の精度を確認
8. 納得できたら **「前週分を反映」** → **「毎週木曜の自動実行をON」**

## 判定ルール（ルート0）

カレンダーの**イベント名**で判定します。すでに定着している運用表記をそのまま使うので、
新しいルールを覚える必要はありません。

| 区分 | イベント名のパターン（`CONFIG.CALENDAR`） |
|---|---|
| 求職者面談として拾う | `キャリア相談予約` `担当A` `担当B` `Lリーチ経由` `電話面談` `再面談` |
| 面談数にカウント | `面談済` |
| 予約数からも除外 | `面談見送り` `サービス利用不可` `中止` |

- 「朝礼」「全体定例MTG」などの社内予定、`◯◯様×◯◯社 オンライン一次面接`（企業側の面接、KPI表では12行目）は拾いません。
- キャンセル・リスケは**予約数には含め、面談数には含めません**（実行率が正しく出ます）。
- リスケで同じ人が同じ週に2件並ぶ場合は、氏名で1件にまとめます（`dedupeByName`）。

**この方式が成り立つ前提は「面談したらイベント名の先頭に『面談済』を付ける」という今の運用が続くことです。**
表記が変わると面談数がずれるので、運用を変える場合は `CONFIG.CALENDAR.heldPattern` も合わせて変えてください。

## 運用

| メニュー | 動作 |
|---|---|
| カレンダー＋LINE統計 > 前週分を反映 | 前週の面談予約数・面談数・LINE登録人数を書き込み |
| カレンダー＋LINE統計 > 期間を指定して反映… | `2026-06-01,2026-08-09` のように指定して過去分を一括反映 |
| カレンダー＋LINE統計 > カレンダーの数字を表と照合 | 書き込まず、手入力値との差分だけ表示 |
| カレンダー＋LINE統計 > LINE統計の数字を表と照合 | 同上（LINE登録人数） |
| カレンダー＋LINE統計 > 拾ったカレンダー予定を一覧表示 | 判定結果の内訳をログ出力 |
| カレンダー＋LINE統計 > 毎週木曜の自動実行をON | 毎週木曜8時台に前週分を自動反映 |
| API連携から取得 / CSV取り込みから反映 | 各ルートの同等メニュー（自動実行は月曜7時台） |
| 自動実行をすべてOFF | トリガーを削除 |

自動実行は常にどれか一つのルートだけが有効になります。

**ルート0の自動実行が木曜なのは、LINE統計の反映に最大3日かかるためです。**
月曜に実行すると前週日曜分がまだ確定していません。木曜なら定例MTG（12:00）の直前に最新化できます。
面談数だけなら月曜でも問題ないので、必要なら `CONFIG.TRIGGER.freeWeekDay` を変更してください。

### 手入力との共存

初期設定は `CONFIG.SHEET.overwriteExisting = false` です。
**すでに人が入力しているセルは上書きせず**、数字が食い違う場合のみ
`Lステップ同期ログ` シートに差分を記録します。
照合して問題なければ `true` に変えると、常に自動取得値で更新されます。

### 記録シート

自動で2つのシートが作られます。

- `Lステップ_RAW` … 週次の集計値（監査・突き合わせ用）
- `Lステップ同期ログ` … 実行日時・対象週・書き込み結果・スキップ内容

## 既知の制約・注意点

### LINE登録人数（ルート0）は近似値です

LINE統計APIが返すのは「その日時点の友だち数」であって「その日の新規登録数」ではありません。
そのため次の式で近似します。

```
週の新規登録数 ≒ (followers + blocks) の週末値 − 週初前日値
```

`followers` はブロック中を除いた友だち数、`blocks` はブロック数なので、
その合計は「延べ追加人数」に近い値になります。
友だちが自分でアカウントを削除した分は追えないため、**実数よりわずかに小さく出ることがあります。**
実数が必要なら、ルートA（API連携）かルートB（CSV）を使ってください。

運用に乗せる前に「LINE統計の数字を表と照合」で過去数週の差を確認することをおすすめします。

### 面談予約数はカレンダーの運用表記に依存します

面談数は検証した2週とも完全一致しましたが、予約数はキャンセル・リスケの書き方によって
±1程度ずれる可能性があります。定期的に「カレンダーの数字を表と照合」で確認してください。

### その他

- **LINE登録率（7行目）は対象外です。** 分母のPV数（5行目）がLステップ外のデータのためです。
  なお2026年4月以降（FE列＝4/6の週 以降）のPV数セルは `=iferror(FE4/FE3,"-")` という
  壊れた数式になっており、登録率は `-` 表示のままです（本スクリプトは5行目を触りません）。
- ルートA・Bの「LINE登録人数」は後からブロックされた友だちも含めて集計します（`CONFIG.COUNT_STATUSES`）。
- ルートA・Bで面談数を取る場合は、Lステップ側に日付型の友だち情報欄
  （「面談予約日」「面談実施日」）を用意し、自動セットされるようにしてください。

## テスト

```bash
node test/run_tests.js
```

週境界の計算（月曜始まり／日曜またぎ／年またぎ）、日付パース、週次集計、CSVパース、
**実際のカレンダーイベント名を使ったカレンダー判定（面談数がKPI表と一致することの検証）**、
ルート間の集計結果の一致、実KPI表の全74週分の列マップとの突き合わせを検証します。
