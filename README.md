# Lステップ → KPI表 自動反映

KPI表（シート `（新）20244～`）の週次KPIを、Lステップのデータから自動で集計・転記する Google Apps Script です。

## 反映される項目

| KPI表の行 | 項目 | 反映方法 |
|---|---|---|
| 6行目 | **LINE登録人数** | 友だち登録日時を週次で集計して書き込み |
| 8行目 | **面談予約数** | 友だち情報「面談予約日」を週次で集計して書き込み |
| 9行目 | **面談数** | 友だち情報「面談実施日」を週次で集計して書き込み |
| 10行目 | 面談実行率（5/4） | **シートの既存数式が自動計算**（`=9行/8行`） |
| 11行目 | LINE登録からの面談移行率（5/2） | **シートの既存数式が自動計算**（`=9行/6行`） |
| 7行目 | LINE登録率（2/1） | 数式は入っているが、分母のPV数（5行目）はLステップ外のデータのため対象外 |

率は全週列にすでに数式が入っているため、スクリプトは触りません。
**書き込むのは6・8・9行目の3つだけ**で、率・月計（「計」列）・年間累計は自動更新されます。

シートの列は「1行目の週開始日（月曜）」で特定します。全74週分が月曜始まり・
終了日=開始+6日であることを検証済みです（`test/run_tests.js`）。

---

## 取得ルートは2つ。どちらか選んでください

同じ集計・書き込み処理を共有しているので、**後から切り替えても結果は変わりません**
（テストで両ルートの集計結果が一致することを確認しています）。

### ルートA：API連携（完全自動）

Lステップの標準APIから直接取得します。人の操作はゼロ。

- **必要なもの**：プロプラン以上＋API連携オプション（月額11,000円税込、Webhook利用中なら+5,500円）
- 管理画面「API連携 > 認証」でアクセストークンを発行して設定

### ルートB：CSV取り込み（オプション不要・全プランで使える）

Lステップからエクスポートした友だちCSVを、決まったGoogleドライブのフォルダに置くだけ。
**置いた後の集計・転記・率の更新はすべて自動**です。

- **必要なもの**：なし（CSVエクスポートは全プラン共通機能）
- 手間：週1回、管理画面「友だち管理 > CSV操作 > エクスポート」→ ドライブに保存、の2ステップだけ

まずルートBで動かして数字を検証し、運用が固まったらルートAへ、という進め方が安全です。

## ⚠️ 着手前に必要な準備

### 1. KPI表を Google スプレッドシート形式に変換する（両ルート共通・必須）

現在このファイルは **Excel形式（.xlsx）のまま Drive にあります**。
Excel形式のファイルには Apps Script を紐づけられず、`SpreadsheetApp` から開くこともできないため、
**このままではどちらのルートも動きません。**

Google スプレッドシートで開き、`ファイル > Google スプレッドシートとして保存` を実行してください。
変換後は新しいファイル（新URL）になるので、共有リンクの貼り替えと、
変換直後に「計」「累計」列の数値が変換前と一致するかの確認をおすすめします。

### 2. 面談予約数・面談数をLステップ側で「日付」として持たせる（両ルート共通）

Lステップから取れるのは友だちの登録日時・タグ・友だち情報です。
**面談の予約日／実施日を日付として保持していないと、週次で数えられません。**
日付型の友だち情報欄を2つ用意し、自動でセットされるようにしてください。

- 「面談予約日」… 予約完了時のアクションで当日日付をセット
- 「面談実施日」… 面談実施のタグ付け／アクション時に当日日付をセット

こうすると「その週に予約が入った件数」「その週に面談を実施した件数」という
**KPI表と同じ“週次イベント数”の定義**で集計できます。
登録週と面談週がまたがっても正しい週に計上されます（テスト済み）。

日付欄をすぐ用意できない場合の暫定手段として `CONFIG.MEETING.mode = 'tag'` もありますが、
「友だち登録週」に寄せて数えるため実績とずれます。恒久運用には非推奨です。

## セットアップ手順

### 共通

1. 変換後のスプレッドシートを開き、`拡張機能 > Apps Script`
2. `src/` 配下のファイルと `appsscript.json` の内容をコピー
   （`clasp` を使う場合は `clasp create --type sheets` 後に `clasp push`）
3. スプレッドシートを開き直すと、メニューに **「Lステップ同期」** が追加されます

### ルートA（API連携）の設定

4. `プロジェクトの設定 > スクリプト プロパティ` に登録

   | プロパティ名 | 値 |
   |---|---|
   | `LSTEP_ACCESS_TOKEN` | 管理画面「API連携 > 認証」で発行したトークン |
   | `KPI_SPREADSHEET_ID` | KPI表のスプレッドシートID（バインド型なら不要） |

5. `src/00_Config.gs` の `CONFIG.API` を、管理画面
   **「API連携 > APIリファレンス」の「友だち情報一覧取得」** に合わせて書き換え

   ```js
   API: {
     baseUrl: 'https://…',        // ← リファレンス記載のホスト
     friendsPath: '/…/friends',   // ← 「友だち情報一覧取得」のパス
     method: 'get',               // ← リファレンスのメソッド
     …
   }
   ```

   リファレンス画面の **【cURL実行サンプル】** をコピーすると、URL・メソッド・ヘッダーが確実に分かります。

6. メニュー **「API連携から取得 > API接続テスト・項目診断」** を実行
   → 実レスポンスのキー一覧と自動マッピング結果がログに出ます。
   `null` の項目があれば、ログのキー名を `CONFIG.FIELDS` / `CONFIG.MEETING` の候補配列に追記
7. **「書き込まずに確認（直近8週）」** で既存の手入力値と照合
8. 問題なければ **「毎週月曜の自動実行をON」**

### ルートB（CSV取り込み）の設定

4. Googleドライブに専用フォルダを作り、そのIDを `CONFIG.CSV.folderId` に設定
   （フォルダを開いたときのURL `…/folders/★ここ★`）
5. Lステップ管理画面「友だち管理 > CSV操作 > エクスポート」でCSVを出力し、
   そのフォルダに保存（同じフォルダに溜めていけば、常に最新のCSVが使われます）
6. メニュー **「CSV取り込みから反映 > CSVの列名・集計結果を確認」** を実行
   → 列名・自動マッピング結果・直近8週の集計値がログに出ます。
   列名が違う場合は `CONFIG.FIELDS` / `CONFIG.MEETING` に実際の列名を追記
7. 数字が合っていれば **「最新CSVで前週分を反映」**
8. 運用に乗せるなら **「毎週月曜の自動実行をON」**
   （CSVを置き忘れた週は、前回のCSVで再計算されるため必ずログを確認してください）

## 運用

| メニュー | 動作 |
|---|---|
| API連携から取得 > 前週分を反映 | 前週（月〜日）の3項目を書き込み。定期実行と同じ処理 |
| API連携から取得 > 今週分を反映（速報） | 進行中の週の途中集計を書き込み |
| API連携から取得 > 期間を指定して反映… | `2026-06-01,2026-08-09` のように指定して過去分を一括反映 |
| API連携から取得 > 書き込まずに確認（直近8週） | シートを変更せず結果だけ表示 |
| CSV取り込みから反映 > 最新CSVで前週分を反映 | フォルダ内の最新CSVで前週分を書き込み |
| CSV取り込みから反映 > 最新CSVで期間を指定して反映… | CSVから過去分を一括反映 |
| 各ルート > 毎週月曜の自動実行をON | 毎週月曜7時台に前週分を自動反映（既存運用「毎週月曜日に前週の数字を入力」に対応） |
| 自動実行をすべてOFF | トリガーを削除 |

自動実行はどちらか一方のルートだけが有効になります（ONにすると他方は解除されます）。

### 手入力との共存

初期設定は `CONFIG.SHEET.overwriteExisting = false` です。
**すでに人が入力しているセルは上書きせず**、Lステップ側の数字と食い違う場合のみ
`Lステップ同期ログ` シートに差分を記録します。
数字を照合して問題なければ `true` に変えると、常にLステップ側の値で更新されます。

### 記録シート

自動で2つのシートが作られます。

- `Lステップ_RAW` … 週次の集計値（監査・突き合わせ用）
- `Lステップ同期ログ` … 実行日時・対象週・書き込み結果・スキップ内容

## 既知の制約・注意点

- **LINE登録率（7行目）は対象外です。** 分母のPV数（5行目）がLステップの管理外データのためです。
  なお現状、2026年4月以降（FE列＝4/6の週 以降）のPV数セルは
  `=iferror(FE4/FE3,"-")` という壊れた数式になっており、登録率は `-` 表示のままです。
  PV数を入れる運用に戻す場合は、この数式を消す必要があります（本スクリプトは5行目を触りません）。
- 「LINE登録人数」は後からブロックされた友だちも含めて集計します（`CONFIG.COUNT_STATUSES`）。
  “その週に登録した人数”という既存の定義に合わせたものです。除外したい場合は `['normal', '有効']` などに変更してください。
- `dateField` モードでは、1人が複数回面談した場合、Lステップの日付欄が最新日付で上書きされるため
  最後の1件のみ計上されます。再面談を厳密に数えるなら、Lステップ側に回数用の項目を別途持たせてください。
- ルートAでは友だち一覧を毎回全件取得します。友だち数が数万件規模で実行時間（6分上限）に近づく場合は、
  `CONFIG.API.extraQuery` にLステップ側の絞り込み条件を追加してください。
- CSVの文字コードは UTF-8 / Shift_JIS を自動判定します（`CONFIG.CSV.encodings`）。

## テスト

```bash
node test/run_tests.js
```

週境界の計算（月曜始まり／日曜またぎ／年またぎ）、日付パース、週次集計、CSVパース、
**APIルートとCSVルートの集計結果の一致**、および
**実際のKPI表から書き出した全74週分の列マップ**との突き合わせを検証します。
