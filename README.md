# フェース タスク管理ダッシュボード

株式会社フェース向けの、社内タスク管理アプリです。
MTG で決まったタスクを 1 か所に集め、**誰が・いつまでに・いまどうなっているか**を
全社員が同じ画面で把握できるようにします。期限が近づいたタスクは、社内で使っている
**メール**に自動で通知します。

## 解決したいこと

| 困りごと | このアプリでの解決 |
| --- | --- |
| MTG で決めたタスクが進行しているか状況がわからない | タスクごとに状況（未着手／進行中／停滞／完了）と進捗コメントの履歴を持ち、ダッシュボードで全社分を一覧表示。**一定期間更新が無いタスク**を専用の枠で炙り出します |
| リマインドをしたい | 期限の 3 日前・当日・超過後にメールを自動送信。担当者ごとに 1 通へまとめ、同じ内容を何度も送らないよう送信間隔を制御します |
| いつまでに・だれが を把握したい | 期限と担当者を必須の軸として一覧・担当者別ページ・MTG 別ページを用意。担当者未定のタスクも専用枠で表示します |
| 社内ツールはメール | 通知はすべてメール（SMTP）。Slack などの追加ツールは不要です |
| 役員のみのタスクは一部メンバーにしか見せたくない | タスクごとに公開範囲（全社員／役員のみ）を設定。役員・管理者以外には一覧・検索・詳細・通知のすべてで表示されません |

## 画面

| 画面 | 内容 |
| --- | --- |
| ダッシュボード | 未完了／期限超過／今週が期限／状況未報告／今月の完了の指標、自分のタスク、期限が迫ったタスク、状況が更新されていないタスク、担当者別の進捗バー、最近の進捗報告 |
| タスク一覧 | キーワード・担当者・状況・MTG・公開範囲での絞り込みと、MTG で決まったタスクの登録 |
| タスク詳細 | 進捗の報告（コメント＋状況変更）、進捗履歴、タスク情報の編集 |
| 担当者別の進捗 | 誰が何件抱え、何件が期限超過・未報告か。担当者未定のタスク一覧 |
| MTG 別 | 「あの MTG で決めたことが片付いているか」を会議単位で確認 |
| 社員・通知設定（管理者） | 送信予定のリマインド内容のプレビューと手動送信、送信履歴、社員アカウントと役割の管理 |

## セットアップ

```bash
npm install
cp .env.example .env      # SESSION_SECRET とメール設定を記入
npm run seed              # デモ用の初期データを投入（表示されたアカウントでログイン）
npm run dev               # http://localhost:3000
```

`npm run seed` は初期パスワード付きの社員アカウントを 6 名分作成します
（管理者 1・役員 1・社員 4）。役員限定タスクが管理者・役員にだけ表示されることを、
アカウントを切り替えて確認できます。データを作り直す場合は `npm run seed -- --force`。

### 本番向けの設定

- **データベース** — 既定はローカルの SQLite ファイル（`data/maiko.db`）です。
  Vercel などファイルが永続しない環境へデプロイする場合は、`DATABASE_URL` に
  Turso（libSQL）の URL と `DATABASE_AUTH_TOKEN` を設定してください。コードは同じまま動きます。
- **セッション** — `SESSION_SECRET` に推測できない値を設定してください。
- **メール** — `SMTP_HOST` / `SMTP_PORT` / `SMTP_USER` / `SMTP_PASSWORD` / `MAIL_FROM` を設定します。
  未設定、または `MAIL_DRY_RUN=1` のあいだは送信せず、送信内容をサーバーログに出力します
  （設定前でも通知内容を確認できます）。

## メール通知の動き

| 種別 | 送信条件 | 再送間隔 |
| --- | --- | --- |
| 期限超過 | 期限を過ぎた未完了タスク | 1 日 |
| 本日が期限 | 期限が当日 | 1 日 |
| 期限が近い | 期限まで `REMIND_DUE_SOON_DAYS`（既定 3）日以内 | 2 日 |
| 状況が未報告 | `REMIND_STALE_DAYS`（既定 7）日以上、進捗が更新されていない | 7 日 |

- 1 人の担当者宛に 1 通へまとめて送るため、タスク数が増えてもメールは増えません。
- 送信内容と履歴は「社員・通知設定」画面で確認できます。
- 役員限定タスクは、担当者が役員・管理者の場合にのみメール本文へ載ります。

### 定期実行

`GET /api/cron/reminders` が 1 回分の送信処理です。`CRON_SECRET` を設定した場合は
`Authorization: Bearer <CRON_SECRET>` が必要になります。

- Vercel — `vercel.json` に平日 9:00（JST）のスケジュールを定義済みです。
- 社内サーバー — cron から `curl` で叩いてください。

```
0 9 * * 1-5 curl -sS -H "Authorization: Bearer $CRON_SECRET" https://<ホスト>/api/cron/reminders
```

## 公開範囲（役員限定タスク）の扱い

- 公開範囲は `全社員` と `役員のみ` の 2 種類。`役員のみ` は **役員・管理者** だけが閲覧できます。
- 絞り込みは画面側ではなく、データを取り出す SQL（`lib/tasks.ts`）で行っています。
  一覧・検索・詳細・進捗履歴・ダッシュボードの集計・メール通知のすべてが同じ判定を通ります。
- 権限の無いタスクの URL を直接開いた場合は「見つかりません」を返し、
  タスクの存在自体がわからないようにしています。
- 役割の変更は管理者が「社員・通知設定」画面から行います。

## 構成

```
app/
  (app)/            ログイン後の画面（ダッシュボード・一覧・詳細・担当者別・MTG別・管理）
  api/cron/reminders/  定期実行用エンドポイント
  actions.ts        フォームの処理（サーバーアクション）
  globals.css       デザイントークンと共通スタイル
components/         画面共通の表示部品
lib/
  types.ts          役割・状況・公開範囲の定義
  db.ts             スキーマと接続
  auth.ts           ログインとセッション
  tasks.ts          タスクの読み書き（公開範囲の判定はここに集約）
  reminders.ts      通知対象の判定とメール送信
  mail.ts           SMTP 送信（未設定時はログ出力）
scripts/seed.ts     デモ用初期データ
```

技術スタックは Next.js（App Router）+ TypeScript + libSQL/SQLite です。
配色・角丸・フォントは `app/globals.css` 冒頭の CSS 変数にまとめてあるので、
コーポレートサイトに合わせた色へ変更する場合はそこだけを差し替えてください。
