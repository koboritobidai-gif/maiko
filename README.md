# naruトレ（naru-tore v2）

パーソナルトレーナー **naru** が監修する、自宅トレーニングアプリです。
「家でも筋トレできるように」「初心者から上級者まで自分に合った強度で」
「多くの人に運動習慣をつけてもらう」ことを目的にしています。

- 登録不要。データはすべて利用者の端末（localStorage）にのみ保存されます
- 自宅（器具なし）とジム（マシン・バーベル）を切り替えられます
- テーマ別ワークアウトを15プログラム・108ワークアウト収録
- ウォーキング／ランニングをGPSで記録できます
- スマホのホーム画面に追加して、アプリのように使えます（PWA）

## 開発

```bash
npm install
npm run dev        # http://localhost:3000
npm run build      # 本番ビルド
npm run start      # 本番サーバー
npm run typecheck  # 型チェック
```

Next.js 16（App Router）/ React 19 / TypeScript / Tailwind CSS v4。
外部APIやデータベースは使っていないので、Vercel にそのままデプロイできます。

## 画面構成

| ルート | 内容 |
| --- | --- |
| `/` | ホーム。今日のトレーニング、週の進捗、テーマ別ワークアウト、4週間プラン |
| `/onboarding` | 10ステップの初期設定（性別・年齢・場所・部位・目標・レベル・強度・ペース・器具・体格） |
| `/workouts` | ワークアウト集。自宅／ジム／ウォーキングとランニングのタブ、部位フィルタ |
| `/workouts/[id]` | プログラム詳細。Day選択・種目リスト・naruの解説動画枠 |
| `/workout/[id]/preview` | ワークアウトの内容確認（セットごとの種目リスト） |
| `/workout/[id]` | 実行画面。タイマー・休憩・フォームのポイント・音と振動 |
| `/workout/[id]/complete` | 完了画面。体感（RPE）から次回の強度を自動調整 |
| `/cardio` | ウォーキング／ランニングのGPS記録 |
| `/library` ・ `/library/[id]` | 種目一覧と種目詳細（ポイント／よくあるミス／呼吸） |
| `/progress` | 記録。毎日／カレンダー／データの3タブ |
| `/settings` | 場所／目標／強度／ペース／部位／器具の変更、データ削除 |

ワークアウトIDは2種類あります。`w1d3` は4週間プランの1日、`p~six-pack~0` は
テーマ別プログラムの1日です。どちらも同じ実行画面（`/workout/[id]`）で動きます。

## naru本人のお手本動画を追加する

種目データ（`src/lib/exercises.ts`）の `video` フィールドを埋めるだけで、
**実行画面と種目詳細の両方に自動で表示されます**。アプリ側の改修は不要です。

1. 動画を `public/videos/{種目id}.mp4` に置く（ループ再生・音声なし前提。5〜10秒程度の短いクリップが最適）
2. サムネイル用の静止画を `public/videos/{種目id}.jpg` に置く（任意）
3. `src/lib/exercises.ts` の該当種目を書き換える

```ts
{
  id: "squat",
  name: "スクワット",
  // …
  video: {
    src: "/videos/squat.mp4",
    poster: "/videos/squat.jpg",
    caption: "naru / 正面アングル",   // 任意
  },
},
```

`video: null` の種目は、部位をハイライトしたシルエットと
「naruの動画は準備中」というラベルが表示されます。
撮影済みの本数は `/library` の画面上部（「お手本動画 0/49 本」）で確認できます。

> 動画は 720p 程度・数百KB〜数MBに圧縮してください。
> 本数が増えて `public/` が重くなってきたら、`src` を外部の配信URLに変えるだけで移行できます。

## テーマ別ワークアウト（プログラム）を追加する

`src/lib/programs.ts` の `PROGRAMS` に1件足すだけです。
中身の種目はプラン生成と同じロジックで自動的に組まれるので、
種目を足せばプログラムの内容も自動で更新されます。

```ts
{
  id: "core-30",
  title: "体幹強化30日",
  subtitle: "毎日10分の体幹メニュー",
  place: "home",              // home / gym
  rotation: ["abs", "back"],  // 日ごとに狙う部位のローテーション
  dayCount: 30,               // 「30ワークアウト」と表示される
  minutesPerDay: 10,
  level: "beginner",
  intensity: 3,
  tone: "mint",               // カードの配色
  video: null,                // naruのプログラム解説動画
}
```

`stretchOnly: true` にするとストレッチだけのプログラムになります。
自宅プログラムで器具を前提にしたいときは `requires: ["dumbbell"]` を指定します。

## 種目を追加する

`src/lib/exercises.ts` の `EXERCISES` 配列に1件足すだけです。
追加した種目は自動的にプラン生成の候補になり、`/library` にも並びます。

```ts
{
  id: "reverse-lunge",          // 一意なID（動画ファイル名にも使う）
  name: "リバースランジ",
  nameEn: "Reverse Lunge",
  parts: ["legs", "glutes"],    // 部位。先頭が主働筋（その部位の日に優先される）
  equipment: ["none"],          // none / chair / dumbbell / band / barbell / machine / cable / bench / pullupBar
  place: "both",                // home / gym / both
  difficulty: 2,                // 1=やさしい 2=ふつう 3=きつい
  measure: "reps",              // "time"（秒）か "reps"（回数）
  phase: "main",                // warmup / main / cooldown
  reps: 12,
  seconds: 45,                  // 目安時間（カロリー計算にも使用）
  met: 5.5,                     // METs。消費カロリー計算に使う
  unilateral: true,             // 左右交互に行う種目なら true
  cues: ["…"],                  // フォームのポイント
  mistakes: ["…"],              // よくあるミス
  breathing: "…",
  video: null,
}
```

## プラン生成の考え方（`src/lib/plan.ts`）

1. **部位のローテーション** — 選んだターゲット部位と目標から、日ごとの狙う部位を決めます
   （減量なら有酸素を多め、増量なら部位を分割、健康維持は全身をまんべんなく）
2. **種目の選定** — その部位の種目を最優先で選びます。`parts` の先頭が狙った部位の種目
   （＝主働筋が一致する種目）をさらに優先するので、脚の日に有酸素種目ばかりが
   並ぶことはありません。ジムではマシン・バーベル種目が自重種目より優先されます。
   その部位の種目が3つに満たないときだけ、他部位で補います
3. **セット構成** — 1セット3〜6種目にしぼり、**同じ種目をセットで繰り返す**構成にします。
   セット数は実際の秒数から逆算し、切り上げ／切り捨ての誤差が小さい方を選ぶので、
   10分/15分/20分/30分のどれを選んでも所要時間がだいたい合います
4. **漸進性過負荷** — 週が進むごとに秒数・回数が約8%ずつ増えます
5. **消費カロリー** — `METs × 3.5 × 体重(kg) ÷ 200` で算出。体重未入力時は標準値を使います

完了画面で「余裕だった／かなりきつかった」を選ぶと強度が1段階変わり、
プランがその場で作り直されます。

## ウォーキング／ランニングの記録

`/cardio` で Geolocation API（`watchPosition`）を使って距離・ペース・消費カロリーを記録します。

- 精度35mより悪い測位点は捨て、実測速度が8m/s（時速約29km）を超える点はGPSの飛びとして無視します
- 地図タイルは配信していません。代わりに通過した座標から**軌跡の形だけ**をSVGで描きます
  （外部サービスに位置情報を送らずに済み、オフラインでも動きます）
- 位置情報を許可しない場合でも、時間・消費カロリーは記録できます。
  トレッドミル用に距離の手入力も用意しています

## データの保存

`localStorage` のキー `naru-tore:v2` に、プロフィール・プラン・記録・体重・水分・
ウォーキング記録・設定を保存します。位置情報を含め、サーバーには何も送信していません。
マイページの「データをすべて削除」で消去できます。

## 見送った機能

- **地図の表示** — 地図タイルの配信元が必要で、位置情報を外部に送ることになるため。
  ルートの形はSVGで自前描画しています
- **歩数計** — ブラウザから歩数センサーを読む標準APIがなく、
  ネイティブアプリかヘルスケア連携が必要です
- **カメラでマシンを認識** — 画像認識モデルの用意と学習データが必要で、
  Webアプリ単体では実用的な精度を出せません
